# stapes

`stapes` is a terminal-based audio authoring environment and sequencer. It runs entirely on the [`lixenwraith/audio`](https://github.com/lixenwraith/audio) engine and the banks it ships, the ones [vif](https://github.com/lixenwraith/vif) plays, and provides a reflective, command-driven interface over the TOML audio specifications, with the rip, which hears a recording into them, and the trainer of the rip's model. It was soundlab inside vif until it left with its command and its trainer; the stapes is the ear bone that carries sound inward.

Supports interactive REPL, TUI, and headless script execution. [Stapes](doc/stapes.md) is its design: what it offers, its files, MIDI and the rip's verbs.

## The package

The package `stapes`, at the module root, holds the session, its documents, the verb table and the TUI, which runs over any `terminal.Terminal` and takes a host's own speakers as its sink; `cmd/stapes` adds the flags, the REPL and the process's terminal and signals. It is a package to import, not an `internal/` one, so that a host with its own screen and speakers, Android's to come, runs it in-process: `ResolveFiles` fills the `Files` a session reads, `NewSession` opens one from `Options` (the backend or the host's sink, the volume, the log's writer and those files), and `RunTUI` draws it on a terminal. `RunScriptFile` runs a `.slab` script in it.

## Build

Go as `go.mod` names it; the release is built with cgo off:

- `make release`: a stripped, trimmed `bin/stapes`; `make dev` one with the race detector.
- `make install`, `make uninstall`: the binary, the licence and the docs under `PREFIX` (`/usr/local`, or `~/.local` for a user who cannot write `/usr/local/bin`); uninstall keeps the root.
- `make test`, `make verify`: the race suite, which renders and hears music for twenty minutes on four cores (CI runs it as six jobs side by side), then vet, `gofmt` and the FreeBSD and Android builds.
- `make venv`, `make smoke`: the trainer's Python with a CPU PyTorch, and the training path end to end at smoke scale in a temporary folder ([rip-train](tool/rip-train/README.md)).

## Architecture & Concepts

- **Document vs Registry**: Edits mutate the working document in memory. The audio engine operates on the live registry. `apply` pushes document state to the engine (enabling auditioning); `revert` overwrites the document with the canonical registry state.
- **Dotted Path Addressing**: The command grammar interacts directly with Go reflection over `toml` tags. Paths like `blip.layer.0.source.freq` are type-checked and routed to exactly what the TOML deserializer sees.
- **Zero-Value Masking**: Pointer chains and zero values indicate "unset" or "package default", preserving minimal explicit TOML generation via `omitempty`.
- **Validation Bounds**: The REPL bounds checks are purely structural (type width, float finiteness). Domain-specific validation (Nyquist bounds, envelope durations) happens synchronously at `validate` and `apply`.
- **Slots**: 0 rhythm, 1 melody, 2 fill, 3 bass, as vif draws them; a melody pattern carries no bass, so slot 1 alone is the melody as authored. The engine's phrase auto-fill is off in stapes so slots stay deterministic; `fill on` restores it to audition the fill bank.
- **Audition**: `play`, `hit` and `export` render a spec as authored; vif's per-sound volume and shape table is not applied.
- **Scripts**: `-s <file.slab>` runs a script and exits; `run <file.slab>` runs one in the session in hand, its relative paths read from the script's own directory, so a recipe beside its files runs from anywhere (a nested `run` from its own); from the REPL or the TUI's command line, so a recipe (rip, compress, save) is one word. A line that fails stops the script with its number; `quit` in it ends the script alone.
- **Voices**: the tonal instruments are `[[voice]]` entries of the sound document, listed by `ls voice`, made by `new voice`, edited by path like a sound and applied into the running mixer, where the next note takes the new voice; a new name is a new instrument a pattern's track names. They load and save with the sounds.

## How rip works

`rip` listens to a recording and writes what stapes needs to play it back: the tempo and where the bars fall, the key and the chord each bar leans on, the drum hits, the melody and bass lines as patterns on the sixteenth grid, the voices that play them, and a song that plays the bars in order. All of it is the engine's own vocabulary, so the result plays at once in stapes and in a game on the same engine, and is checked by ear and by number against the recording.

Two halves meet in the middle. Ripping turns a recording into patterns; training teaches a model to hear the recordings ripping starts from. Both run on the same engine, and either front end, the built-in analysis or the trained model, feeds the same decoders.

```text
  RIPPING                                         TRAINING
  recording (WAV)                                 patterns: the bank's and generated ones
      |                                               |
  1 hear     spectrogram -> front end -> frames   engine renders loops; labels are exact
      |      (the analysis, or the model) <---+       |
  2 read     tempo, bars, key, drums, lines   |   room, mix and voices drawn per loop
      |                                       |       |
  3 write    patterns, voices, transcript     |   log-mel frames + labels -> trainer
      |                                       |       |
  4 compress a dictionary of bars, a song     +------ weights (ripmodel.bin)
      |
  5 refine   render, compare with the recording, keep what sounds closer
      |
  6 check    truths, two rips as witnesses, the bench
```

### 1. Hearing: from sound to frames

The recording is read at 22.05 kHz and cut into frames, a 93 ms window every 11.6 ms, about 86 frames a second. Its tuning is read first, the cents its notes sit off A440, so a recording forty cents flat reads as in tune and every later step works on its own pitch table.

A front end hears the frames into the same fields per frame: how strongly something starts (the onset), each drum's strength (kick, snare, hihat), the salience of each of 69 pitches from E1 to C7, and each register's chroma. The decoders after it never know which front end heard.

- **The analysis** is signal processing. Each frame is split into a harmonic and a percussive part by medians across time and across frequency; each drum's onsets are read in its own band; a pitch's salience is the sum of its partials, the bass register's also read from a window four times longer, which tells semitones apart at 110 Hz.
- **RipModel** (`ripmodel`) is the model, a transformer over log-mel frames: 229 bands from 30 Hz up, under a semitone apart from A3, each read in dB against the frame's own level, which it reads apart, so a soft phrase reaches it as clearly as a loud one. Each frame attends to 64 frames on either side (0.74 s) through four layers of width 256 with eight heads, 3.3 million weights run in pure Go. Its heads give, per frame, the onset, the drums, the pitches and whether a note sounds, which pitches are struck or let go and how hard, the wave and the 32 voice genes the note is played with, which the analysis cannot say, and the family of instrument playing it (piano, guitar, voice, bass, strings, winds, synth, drums or unknown), which no decoder reads yet. A weight file may also put convolutions before the layers, or split the layers into towers for groups of heads. Stapes hears with the model when its root holds `ripmodel.bin`, and with the analysis otherwise. A notes model beside it, `ripnotes.bin`, convolutions over a harmonic stack with the same 169,928 weights at every pitch, gives the pitches, strikes, releases and velocities in its place, and where each pitch sits in its semitone, from which the rip hears a glide as one bent note.

### 2. Reading: from frames to music

The decoders are shared, classical and cheap. Every threshold lives in `RipParams`, which `tune` searches and the root's `rip.toml` carries.

- **Tempo** from the autocorrelation of the onsets under a prior centred on 120 bpm, within the sequencer's 80 to 200; `rip ... bpm <n>` pins it, the bar line still decoded.
- **Beats** by dynamic programming that holds to the period.
- **The meter** over more than eight bars of beats: the beats as quarters in 4/4 or 3/4, or, where the onsets fall on both thirds of the beat, as dotted quarters in 4/4, 6/8 or 12/8 at three halves of the tempo; a reading other than the first must beat it clearly ([audio §9](https://github.com/lixenwraith/audio/blob/main/doc/audio.md#9-ripping-a-recording)). A step stays a sixteenth and the tempo counts quarters, so a bar of 3/4 or 6/8 is twelve steps. `rip ... meter <n/d>` pins it, the bar line still decoded.
- **The bar line** at the phase whose downbeats carry a kick, no snare and the key's root in the bass, with the snare on the backbeats and the most change of chroma. A phrase that leads into the first bar gets a pickup bar.
- **The key** as the root and scale whose tones hold the most chroma, the bass voting for the tonic, and a chord root per bar.
- **Drums** by peak picking: a kick by its rise under 100 Hz, a hihat by its rise above 5 kHz, a snare in between with noise above 5 kHz, and a hit can be two drums at once. `rip ... nodrums` leaves the drums out of a recording that has none.
- **Notes** by a Viterbi path through the pitch salience that pays to move and to start or end a note. The path is cut into notes, their lag behind the beats taken out, and each note lands on a sixteenth and on the key's nearest degree, a semitone left over kept as an accidental. When the model hears strikes, the melody register's notes start where a pitch is struck instead, as hard as it heard, and last while it sounds or until it hears the key let go (`release`, 0.8), any number at once, the pitch ringing on after that as far as a new strike goes, so a note struck under a pedal's ringing is not lost to the notes still sounding; a strike whose pitch never sounds, that is a stronger melody strike's overtone an octave, a twelfth or two octaves up, or that repeats within `strike_gap` (0.12 s) starts none, and a pitch still sounding starts again only over `strike_again` (0.95) and as the surest strike within a tone, since a new note's attack sets off strikes on the notes ringing, as sure as its own a semitone or a tone away.
- **Lines.** A model that hears strikes reads both registers by them, any number at once, the bass line's own notes kept only where no strike sounds and strong enough to be sure, and a low note with little sound at its own pitch dropped; the notes are then held to the recording, each note's harmonics fitted together with the others' and the sound at its first partials remembered through its start, so a note whose sound the others account for goes, a restruck pitch its ring explains and the memory finds no new sound at, a partial of the note under it, a shadow with no fundamental of its own, and a strike the rules dropped comes back where the notes kept leave its sound unexplained; each register's voice plays on a modal bank. Otherwise the melody register, from F3 up, is decoded as two lines at once, so a slow line under a pluck is heard too; a second-line note is kept where it reaches `second_voice` (0.5) of the first's strength. The notes are then parted again by what a line keeps: its pitch from note to note, the length and strength of its notes, never two at once. Which line is the melody is a rule, the busier by default (`rip ... lead`). The bass is decoded up to A3, and a note both registers hear goes to the line it continues.

### 3. Writing: from music to patterns

- **Patterns** of up to `bars` (4) bars of the meter per part, `<name>_beat_1`, `<name>_melody_1` with the second line as a track of its own, `<name>_bass_1`, and on, added to the document and playable at once; the transport takes the tempo, meter, key and tuning.
- **Voices.** Each line gets one, fitted by ear: the engine plays a candidate voice at the line's longest and loudest notes, at the recording's pitch, loudness and tuning, compares the render's mel frames with the recording around each note, and searches the 32 genes and the wave from every registered voice and, through the model, from the voice its head heard, the genes of every note averaged over the line. They are `<name>_melody_voice`, `<name>_under_voice` and `<name>_bass_voice`; `fit` searches again, longer.
- **The transcript** keeps every note in seconds before the grid, with how much of the recording's salience supports it and, for a melody note, how bright it is. `notes` lists it and writes it as a MIDI file to correct in a sequencer.

A rip is kept under its name for the session, so `fit`, `compress`, `refine` and `song` need no file.

A MIDI file is a rip already: `rip score.mid name` hears nothing, its notes the transcript and its drum channel the hits, the tempo the file's first, the bars its time signature's from where it starts, read at the tempo folded into the sequencer's range (3/8 at 70 bpm is 3/4 at 140), the key from its notes' pitch classes; each line plays a copy of the shipped voice its General MIDI program plays on, the piano where it sets none. `compress`, `song`, `notes`, `agree` and `truth` work on it as on a recording's rip, so a score is heard beside the rip of the same piece; what hears the recording (`fit`, `refine`, `song ... score`, `notes`' support) has none to hear.

### 4. Compressing: bars into a song

`compress` turns the rip's bars into as few one-bar patterns as it can. Per part, two bars differ by the steps they do not share over the steps either has; bars within `percent` (5) of each other in the notes, `beat percent` (40) in the beat, form a group whose middle bar stands for it (`<name>_<part>_a`, `_b`, ...), and a search refines which bar joins which. The beat's is wide because a rip errs by scattered hits, one in a bar of twelve 8%, where a drummer changes many at once. The song `<name>` lists the patterns each bar plays at the recording's tempo, meter, key and tuning, on the recording's drums: each kit piece the rip read gets an eq of the recording's tone against its own and a level against the kick as the recording has it, `<name>_kick`, `<name>_snare`, `<name>_hihat` in the sound document, which `save sound` keeps beside the song. A first bar that starts partway takes the beat of the bar most like it, so what the rip heard before the music leaves the song. `song <name>` shows it, `song <name> <file.wav>` renders it, `song <name> play` conducts it through the live sequencer. Its render is ripped back on its own grid and scored against the rip, so what compressing lost is a number.

### 5. Refining: closing the loop

The engine is the ground truth of its own vocabulary, so a rip is good when its render sounds like the recording. `refine` works in rounds: it fits the voices again, then tries each tonal step a semitone and an octave either way, at the recording's strongest pitch there, a step earlier or later, longer or shorter, and silent, and tries the strongest pitch where a line is silent. A move stays when the bars that play it sound closer to the recording, the render and the recording heard through one front end and their pitch salience, mel bands and onsets compared bar by bar. A voice may not drift more than a tenth from its fit to the notes.

### 6. Checking: how good a rip is

- `truth` scores a rip against notes given: a transcript corrected by hand, a rhythm tapped out, or a MIDI file, whose drum channel scores the kicks, snares and hihats hit by hit. Its first row counts every note by pitch and onset, whatever line holds it, the count a round or a search is picked by; then per line it counts the notes heard as given, those missed and those extra, and, for notes with pitches, those heard by how loud the recording plays them, in 6 dB bands under its loudest tenth, alone or under other notes. `timed` takes a truth annotated on the recording's own clock as it stands, no time map fitted and no transposition tried.
- `agree` compares two rips of one piece where no score exists.
- `live` hears a recording as it would play, fed in blocks to the library's stream: each bar is said as it freezes, with how far behind the sound, and the stream is then measured against the offline rip of the same recording, which comes under the name as `rip` brings it.
- `bench` rips fresh loops the engine renders, whose answer is known, clean and through a room and a mix, and scores the analysis and the model side by side; with `meters` a third are in 3/4 or 6/8, each meter graded apart.
- `tune` searches the decoders' thresholds over rendered loops, or with `truth` the model's over real recordings against their truths, from the current thresholds outward, by the mean over the list's conditions, a set refused that costs any of them more than a guard.

What a rip does not tell apart yet: a bass note's attack from a kick, a plucked chord's attack from a snare, a change of key from accidentals, and a third line or the chord a pedal rings, which two lines cannot hold. Soft notes are heard less often than loud ones.

### 7. Learning: how the model is trained

The model learns from music the engine renders itself, since the engine knows exactly what it played.

- **Generating.** `corpus` renders loops of `bars` (4) bars from the registered rhythm, melody and bass patterns across tempos and keys. With `gen`, three loops in five per part play a beat, a melody or a bass line drawn from the key instead, and an accompaniment in the free slot, a broken chord under a melody of longer notes; a third of the generated melodies and accompaniments play half their length 6 to 18 dB softer, as a phrase played softly, and a generated loop leaves out its drums three times in ten and its bass once in seven, so a line is heard bare too. With `meters`, a third of the loops are in 3/4 or 6/8 with every part generated in it: the beat strikes the bar's first beat against its others, and a compound meter's melody and bass keep to its eighths.
- **Labelling.** Each loop is kept as its log-mel frames and, per frame, what the engine played: the onsets, the drums, the pitches sounding, where each pitch is struck and let go and how hard, the wave and 32 genes of each note's voice, and the family each note and hit sounds as: a voice's by the registered voice its genes stay near, unknown when they stray from every one or `aug` drives it, a hit the drums'. The labels cost nothing and are exact.
- **Roughening.** With `aug`, each loop's voices are redrawn near the registered ones, a third of them on another wave, in a third of the loops with a pedal's long releases; the mix passes through a room drawn per loop (a gain and swell, a low-pass, two equaliser bands, a soft clip, a compressor, a booth's or a hall's reverb, a noise floor), and the loop plays off A440 by up to a quarter tone. The labels stay the notes as played.
- **Training.** `tool/rip-train` holds the model's PyTorch twin. It trains on random six-second windows of the loops (512 frames, eight a step), scores the loops it holds out every thousand steps and keeps the best, and writes the weight file the Go model loads, the two agreeing to float32 rounding.
- **A round.** `tool/rip-train/pipeline.sh` renders the corpus in parts at once, trains, benches and installs; 40000 loops and 40000 steps take about four hours on a laptop with a GTX 1060. Weights ship only when they beat the analysis on the bench and on real recordings' truths; [Rip design §8](doc/rip-design.md#8-measured-on-the-sample-recording) holds the rounds' numbers to 12a, [Rip training](doc/rip-training.md) the later ones and the data byte by byte from a loop to the weight file, and [the trainer's README](tool/rip-train/README.md) the instructions.

### 8. The process, end to end

1. `rip song.wav name` writes the patterns, the voices and the transcript, and sets the transport; `rip song.mid score` does the same from a score.
2. Listen: `slot` the patterns or `render` them to a WAV, and read `notes name`.
3. Check: `truth name score.mid` against a score, or `agree` two rips of the piece.
4. `compress name` writes the dictionary and the song, and `song name play` plays it.
5. `refine name` closes the loop; `fit name` refits the voices alone.
6. Save the patterns, the song and the voices to keep them, as Usage shows next.

[Audio library §9](https://github.com/lixenwraith/audio/blob/main/doc/audio.md#9-ripping-a-recording) is the engine's side of each stage and [Rip design](doc/rip-design.md) the plan and the measurements.

## Usage

```bash
# TUI mode
go run ./cmd/stapes -tui

# REPL mode
go run ./cmd/stapes

# Headless batch processing
go run ./cmd/stapes -headless -s script.slab
```

To rip a recording to a document and hear it, in the REPL or the TUI's command line:

```text
rip song.wav bite nodrums        # the patterns, the fitted voices; nodrums when it has no kit
compress bite                    # the dictionary and the song bite
song bite play                   # conducts it; music stop ends it
save pattern bite_patterns.toml  # the patterns and the song
write bite_melody_voice bite_melody_voice.toml
write bite_bass_voice bite_bass_voice.toml
```

and later, to hear the document again:

```text
load sound bite_melody_voice.toml      # the voices first, registered by apply
apply bite_melody_voice
merge sound bite_bass_voice.toml
apply bite_bass_voice
load pattern bite_patterns.toml        # the patterns and the song that name them
song bite play                         # or: song bite out.wav
```

Put either in a `.slab` file and `run` it. Without the voices the tracks fall back to the shipped lead and bass. In the TUI, `^O` opens the files overlay: `Enter` on a `.toml` loads it, on a `.slab` runs it behind the screen, on a `.wav` or a `.mid` rips it, `m` merges a document, or a `.mid`'s patterns and song, and `s` saves into the directory shown.

### CLI Flags
- `-tui`, `-T`: Full-screen Terminal User Interface. Empty documents are seeded from the built-ins; the REPL and scripts leave that to `builtin`.
- `-headless`: Discard audio output (`-ab null`).
- `-s <file>`: Execute a `.slab` script file line-by-line and exit.
- `-config-dir <dir>`: the root, else `os.UserConfigDir()` plus `stapes` (`~/.config/stapes` on Linux and FreeBSD). It holds, flat, `stapes.toml`, the settings (`[audio] buffer_ms`, the mixer period, 50 ms when unset; a key it has no field for is refused by name), `rip.toml`, what `rip` listens with when it is there and where `tune` writes, `ripmodel.bin`, the model `rip` hears with in place of the built-in analysis, `ripnotes.bin`, the notes model beside it, and `ripjudge.bin`, a judge of the notes model's strikes fitted on those weights ([rip-train](tool/rip-train/README.md)).
- The documents, `music.toml` and `sounds.toml`, are found along the search path, vif's audio folder (`os.UserConfigDir()` plus `vif/audio`) whatever `-config-dir` names: the overrides vif loads are registered and opened as the working documents, each saves back to the file it came from, and an untitled save lands in the search path's first folder, where vif reads it next run. The working directory is never searched.
- `-config-music <file>`, `-config-sounds <file>`: name a document's file outright, read and saved there.
- `-ab <name>`: Force audio backend (`pacat`, `aplay`, `null`, `wav:out.wav`).
- `-vol <f>`: Sound effect volume 0..1 (default 0.7); music keeps its own level.

## TUI

The TUI is a shell over the exact same dispatch table used by the REPL and scripts. Its keys build and execute standard command strings, a recorded take included (`take`), so a script can reproduce everything it does. `Tab`/`Shift-Tab` move the keys between the panes on screen, the same in every view, the pane that has them framed in green, and `Esc` brings them back from the mixer or the log to the view's own pane. `<`/`>` slow the tempo down or speed it up by 5 bpm, `?` shows the keys of the view in hand, `:` opens the command line, `^O` opens the files overlay, `^S` saves modified documents (a first save offers the search path's first folder, where vif reads it next run), and `^Q`/`^C` quits, warning once about unsaved changes.

- **Browse**: the browser beside the mixer, over the log. The browser's tabs are patterns, sounds and voices (`h/l`); a sound's role says whether it is an sfx or a piece of the drum kit. `j/k`, `PgUp/PgDn` and `g/G` move, `/` finds the next name containing a term, `space` plays a sound, a voice's middle C, or puts a pattern in its role's slot (again pauses), `0-3` puts the pattern in a slot or takes it out, on the next bar while the transport runs. `n` makes a new entry and `e` edits the selected one: a pattern in the pattern editor, a sound or a voice in the inspector, which say whether what they hold is new or edited. `Enter` opens the inspector on either (`l/h` fold, `L/H` all, `Enter` edits a leaf, `a` adds, `x` deletes, `Esc` closes). `a/v/r` apply/validate/revert, `u` undoes the last edit, `c/w` clone/write, `+` mixes into another, `p` makes a new pattern of the tracks the editor yanked, `d` twice deletes, `m` resets the transport.
- **Mixer**: every slot on one timeline, as many bars of the transport's meter as fit, under a shared playhead, beside the browser or beneath the editor. `j/k`, `PgUp/PgDn` and `g/G` move a cursor over the slots' titles and tracks, and rows it cannot show scroll under the cursor and stay where it leaves them. `space` or `m` mutes the cursor's slot or lets it sound again: its pattern plays on in time, so it comes back in step. On a track row they mute that track, and `s` solos it: the slot's soloed tracks sound alone. A silent track is drawn dimmed, a soloed one lit; the mutes go when the slot changes pattern, as the log says. `e` edits what the slot plays, and `n` makes a new pattern in it.
- **Pattern editor** (`n` new, `e` edit): one pattern on two tabs, `keys` and `grid`, which `Tab` walks before the mixer; the frame and the header say whether the pattern is new or edited and the slot it plays in. A new pattern starts empty, in the first silent slot (slot 2, the free layer, when all play), beside whatever plays there, so it loops with them before it is ever saved. `Enter` applies the pattern and plays it in its slot; `^R` records a take; `^D` twice deletes the pattern, out of its slot too; `Esc` closes it, kept in the document for `^S`.
  - **keys**: the tonal voices on a drawn keyboard of two octaves and a third from C: `z s x … m` the first octave, `q 2 w … u` the second, `i 9 o 0 p` the third's C to E (`, l . ; /` play the second's again). A dot marks each note of the key `:key` set, its root lit. `↑/↓` voice, `←/→` or `{ }` octave, `- =` velocity, `[ ]` note length, the keys the grid edits a note's with; `\` walks the pattern through 1, 2 and 4 bars of its meter, as many as 64 steps hold, refusing a length that would cut a note off. `^R` plays the pattern and records over its length; `^R` again writes the take into it through `take`, a track per voice played, each note on the degree of the key that sounds it (a note outside the key keeps its pitch as an accidental on the nearest degree), and applies it, so the loop plays it from its next pass. `Backspace` drops the take's last note.
  - **grid**: the tracks on a step grid with a bar ruler and the playhead: a drum hit is a velocity meter, a tonal note its degree, `#` or `b` after it for an accidental, with its length drawn on, a chance under 1 dimmed. `h/l` step, `H/L` a beat, `PgUp/PgDn` a bar, both the pattern's meter's (a beat as the bar is felt, 6/8's a dotted quarter), `j/k` track; `space` toggles a hit or note (a note goes on from the line's last), `1-9 0` and `+/-` velocity, `c` chance, `[ ]` length, `, .` degree, `{ }` octave, `t`/`T` voice in the family or the other family, `f` follow the chord, `m` mutes the track in the slot the pattern plays in, `a` adds a track, `x` twice deletes one, `J/K` move it down or up (`mv`), the cursor with it, the order a build-up brings the tracks in, `y` yanks one, `Y` adds it to the yank or takes it out, `p` pastes the yank into the pattern open (`mix`, below), `s` sets the steps, `u` undoes the last edit, all a key did. `r` shows a tonal track as a piano roll, a row per degree of the key, where `↑/↓` move the pitch and `space` places a note on it.
- **Working**: a verb that takes seconds or minutes (`rip`, `fit`, `compress`, `refine`, `tune`, `bench`, `corpus`, `render`, `song`, `run`) runs behind the screen under a working box that counts the seconds and shows the last lines it said; keys wait for it, `^Q` twice leaves it. A rip from the files overlay ends with the browser on what it heard.
- **Files** (`^O`): a directory's entries over the panes, directories first, then files newest first, opened where it last was, else the pattern document's directory, else the working directory. `j/k`, `PgUp/PgDn` and `g/G` move, `h`/`←`/`Backspace` go up, `Enter` (or `l`) opens a directory, loads a `.toml` document, sounds or patterns by the tables it holds, or rips a `.wav` or a `.mid` under a name a prompt asks for, offered from the file's name; `m` merges a document onto the one in hand instead, and a `.mid`'s patterns and song under a name asked for, landing on them; `s` saves the tab's document, patterns or sounds, into the directory under a name asked for, offered from its own; `Esc` or `^O` closes. A path with a space travels in quotes, which the overlay adds.
- **Size**: below 60×16 the screen shows only a centered notice of the size it needs, and keys other than quit do nothing. A large screen scales the editor: wider steps and taller tracks in the grid, a larger keyboard. Beneath the editor the mixer takes the rest of the screen, over the log's last line.

## Command Reference

`help` prints the full usage of every verb, `help <verb>` describes one and `help keys` lists the TUI's keys.

- **Documents**
  - `load [sound|pattern] <file> [name]`, `merge [sound|pattern] <file> [name]`: replace the document from a file, or overlay a file onto it by name; voices come with the sounds, songs with the patterns. Quote a path with a space. The kind alone names the file, which is read by its tables; a `.slab` runs as a script, and a `.wav` is refused with the `rip` that hears it.
  - A `.mid` (a Standard MIDI File of type 0 or 1) loads as patterns and a song under `name`, the file's name made one when none is given, the transport taking the song's tempo, meter and key; `merge` adds them to the document in place of the patterns an earlier load or `compress` of the name made, `load` replaces the document with them. What the file held that they could not keep is said: a meter change, a tempo change and its bar, a program on its family's voice, a key the kit lacks, notes merged or cut.
    - Patterns: one a part a bar, as `compress` names them (`<name>_beat_a`, `<name>_melody_a`, `<name>_bass_a`, ...), a bar played again the same pattern. The drum channel is the beat, a track a kit piece (kick 35 and 36, snare 38 and 40, hihat 42, 44 and 46, clap 39); a part whose program plays on the bass is the bass, the rest the melody, a track each, named after its MIDI track. Each note keeps its velocity and its length in steps, a step the file's sixteenth, on the key's degree with an accidental for the rest.
    - Voices: a program plays on the shipped voice of its family of eight, the table `write` writes by: pianos, chromatic and pitched percussion on the piano, basses on the bass, guitars and plucked strings on the pluck, organs, strings, ensembles, synth pads and effects on the pad, brass, reeds, pipes and synth leads on the lead.
    - The song plays the patterns in order at the file's first tempo, by octaves into 80 to 200 bpm (a step then two of the file's sixteenths, or half of one), in the key the file signs (its scale the one the notes hold most) or, unsigned, the key its notes hold.
    - Meters: a bar is its time signature's steps at the folded tempo, 3/4 and 6/8 twelve, 3/8 six, 4/4 sixteen, 4/4 before the first signature, and the song and its patterns carry the first; a signature no pattern holds in whole steps (5/32) is read in bars of 16, and a bar a signature change cuts short is a pattern of the steps it has. A bar of another meter than the first is a pattern of its own steps, which the song plays out of time, as it says.
  - `builtin sound|pattern|voice`: seed the document from the built-ins; `sound` seeds the voices too.
  - `save sound|pattern [file]`, `write <name> <file>`: write the document (bare = provenance path), or one entry, a song too, without its patterns. `save` keeps what is its author's in the file the document came from, and carries it to another file: the `[macros]`, the file's own comments and the comment above each entry, kept by the entry's name, while every entry is written anew, as an invocation of those macros where one makes it. A comment inside an entry is lost. Patterns seeded by `builtin` have no file behind them and save over the bank's own document, so their first save is the bank's text with the session's edits; any other document with no file behind it, made in the session, read from a MIDI file or sounds seeded by `builtin`, and `write`'s one entry are written out in full. A document is TOML: `save` refuses a `.mid`.
  - `write <pattern|song> <file.mid>` writes one as a Standard MIDI File of type 1, as `song <name> <file.mid>` does a song: a pattern once through at the transport's tempo, key and chords, a song at its own (the transport's chords where it has none, as `play` hears it), its bars playing the document's patterns, else the registry's.
    - Tracks: a first of the tempo, the key signature (a scale other than major signed as the minor on its root) and the time signature of the pattern's or the song's `meter`, 4/4 when it sets none; then a track a pattern track, by slot, instrument and order, named by its `desc` or its instrument.
    - Voices: each on its General MIDI program, a channel a program: the piano on 0 (acoustic grand), the bass on 32 (acoustic bass), the pluck on 24 (nylon guitar), the pad on 89 (warm pad), the lead on 81 (sawtooth lead), and a voice a document added on the program of the shipped voice nearest it, of its wave first, then by its genes. The drums go on channel 10, the kick on 36, the snare on 38, the hihat on 42 and the clap on 39, a sixteenth each.
    - Notes: each sounds its steps at its velocity, a chord-following track on its bar's chord; a note on a key still sounding in its track ends the one before. Probability and humanize are not written, every event sounding on its step, nor is a song's tuning, MIDI being at A440.
  - `ls sound|pattern|voice|song [glob]`, `show <name>[.path]`: list entries (`*` marks dirty); dump an entry as TOML, or print a leaf value.
  - `new sound|pattern|voice <name>`, `cp <src> <dst>`, `mv <src> <dst>`, `del <name>...`: seed an entry with a minimal valid spec, duplicate, rename or discard one; a discarded entry keeps any applied registry copy.
  - `validate|apply|revert [name|all]`: run the domain validations, push into the live registry, or restore from it; bare or `all` is every entry for `validate`, the dirty ones for `apply` and `revert`.
  - `undo [n]`: step back over the last `n` (1) edits, an edit being a command that changed a document (a nested `run` folds into its line, and every command one TUI key runs is one edit): the entries it changed come back as they were, one it made goes and one it deleted returns, with their order and `*` marks; an entry an apply has since registered stays marked, since the registry and the transport are left as they are. It says what it restored; the history holds the last 100 edits.
- **Editing**
  - `set <name.path> <val>`, `unset <name.path>`: set a leaf field through reflection, or reset it to its zero value.
  - `add <name.path> [at]`, `del <name.path.idx>...`: insert a zero element into a list field at index `at` (bare appends), or delete elements, several at once, each as its path reads before any is deleted.
  - `dup <name.path.i> [j]`, `mv <name.path.i> <j>`: insert a copy of a list element at index `j` (bare, right after it), sharing nothing with it, or move an element to `j`, those between shifting by one: a pattern's tracks, a track's events, a sound's layers, a song's bars (`dup bite.bars.3 5` plays bar 3 again at 5). An edit of a song's lists then lists its bars as `song` does, numbered as the paths address them.
  - `mix <src> <dst>`: append src's tracks or layers into dst, of the same kind; src is unchanged.
  - `cp <pattern>.track.<n>... <new>`, `mix <pattern>.track.<n>... <dst>`, `mix <pattern>.track.<n>... <pattern>.track.<m>`: make a new pattern of the tracks named, from one pattern or several, with the first's role, append them to the pattern `dst`, or merge their notes into track `m`, which keeps its voice: a note the same as one already at its step (place, degree, octave and accidental) is kept once and counted, and a drum track never merges into a tonal one or the reverse. With `del`, tracks move. Tracks of other lengths meet at the least common multiple of their lengths, each repeated to fill it, the destination pattern's own too; past 64 steps the pattern keeps its length and a longer loop is cut, as the command says. A pattern holds 32 tracks.
  - `cp <pattern>.bar.<k>... <new>`: make a new pattern of one pattern's bars, in the order named, every track sliced at the bar lines (a bar is the pattern's meter's, 16 steps in 4/4 and 12 in 3/4 or 6/8, a pattern's last one may be short); a bar named twice plays twice, as a loop or a song built by hand from a rip wants, up to 64 steps.
  - `take <pattern> <voice> <pos>:<midi>[:<steps>[:<vel>]]...`: add a track of a tonal voice playing the notes at their steps, each on the key's nearest degree with an accidental for the semitone left: what the editor's keys write when a recording ends.
  - `split <pattern>.track.<n> <midi>`: part a tonal track at a pitch under the transport's key, for two lines heard as one: its notes from `midi` up stay, the rest go to a new track of its voice right after it. A drum track, or a split that would leave either side empty, is refused with the counts it found.
  - `shift <pattern>.track.<n>... oct|deg|semi|step <±k>`: move every note of the tracks named by `k` octaves; by `k` degrees of the key, carried into the octave; by `k` semitones, the pitch spelt again on the key's nearest degree with an accidental for the rest, as `take` writes it; or by `k` steps, rotated around its pattern's length. A drum track shifts only by step. A note the shift would take past a step's bounds (degree, octave, accidental) refuses the whole shift, naming the note, before any track changes. The grid's `{ }` move one note's octave; there is no key for these, `:` runs them.
- **Audition and transport**
  - `play <name|file.wav> [vol]`, `hit kick|snare|hihat|clap [vol]`, `note <midi> [vel] [steps] [voice]`: audition an entry, a drum, or a voice through the melodic slot, applying a dirty one first; a `.wav` plays as it is.
  - `export <name> <out.wav> [variant]`: render an entry to a WAV.
  - `render <file.wav> [bars]`: write what the slots hold, `bars` (4) bars at the transport's tempo, meter and key, to a WAV through the engine's offline render: a rip's estimate heard without a device.
  - `slot <0|1|2|3> <pattern|-> [fade_ms] [q]`: put a pattern in a slot, `-` for silence; a dirty pattern applies first. The old pattern fades out over `fade_ms` (250); at 0 its notes ring on under the new one.
  - `music start|stop|reset`, `bpm <n>`, `swing <f>`, `fill on|off`, `key <root> <scale> [deg...]`: transport, tempo, shuffle, slot 2's auto-fill and harmony; `tuning [cents]` shows or sets the cents the transport plays off A440, within a semitone: a rip sets the recording's, a song its own when played.
  - `meter [n/d]`: show or set the bar the transport counts and `render` writes, `n` beats of a 1/`d` note, 4/4 to start; a step stays a sixteenth, so 3/4 and 6/8 are twelve steps and 3/8 six. It takes effect at the next bar line while the music plays; a rip, a `.mid` loaded and a song played set it.
  - `mute music|sfx|all|none`, `mute slot <0-3> on|off`, `vol <f>`, `wait <ms>`: mute a channel, or one slot while its pattern plays on in time; the sfx volume (music keeps its level); a scripted pause.
  - `mute track <0-3> <n> on|off`, `solo track <0-3> <n> on|off`: mute track `n` of the pattern a slot plays, or solo it, its pattern playing on in time: a slot's soloed tracks sound alone, its muted ones never. An audition aid the pattern does not save, dropped, as the log says, when the slot changes pattern or an apply moves the tracks.
  - `where`, `stat`: the transport's bar and step in its meter and the slots' patterns, a muted slot and its muted and soloed tracks marked; the backend, play stats, the muted slots and tracks, and dirty entries.
- **Ripping and measuring**
  - `rip <file.wav|file.mid> <name> [bars] [nodrums] [bpm <n>] [meter <n/d>] [lead busy|high|low|loud|soft|long|short]`: hear a recording's beat, melody and bass as patterns of up to `bars` (4) bars of its meter each, as many as 64 steps hold, named `<name>_beat_1`..., take its tempo, meter and key, and fit a voice to each line; `nodrums` leaves the drum part out. A `.mid` file is read, not heard: its lines and drums as `truth` reads them, quantized as a rip's notes are on the file's own ticks, at its first tempo (an octave faster or slower until the sequencer plays it; a change after it is said and played at the first), in bars of its time signature from where it starts, at the tempo folded (4/4 when it names none; a short first bar is a pickup), in the key its notes' pitch classes hold most, each line played by a copy of the shipped voice its program plays on (the table `load` reads programs by; the piano where none is set) under the rip's voice names; a note outside E1 to C7 is dropped and counted, and `bpm`, `meter` and `lead` are refused. The recording's tuning is read first, and a phrase before the first bar line gets a pickup bar; `bpm <n>` reads it at that tempo, the bar line still decoded, for a recording whose tempo is known or wanted on another metrical level, and `meter <n/d>` in bars of that meter, for one whose meter the rip misreads. `lead` names which of the melody register's two lines is the melody once they are parted: the busier by default, the one with the most notes for its sounding time, or the higher, lower, louder, softer, or longer or shorter in its notes when you know the piece.
  - `live <file.wav> <name> [block <ms>] [pace]`: feed a recording to a stream in blocks of `ms` (50) milliseconds, as fast as it takes them, or with `pace` each when its last sample would have sounded, so the run takes the recording's length. Each bar is said as it freezes: where it starts, where the sound was (paced, the clock's time, which counts what the stream took), and how far that is behind the bar's end. The offline rip of the recording then comes under `<name>` as `rip <file.wav> <name>` brings it, and the stream is measured against it: the offline rip's notes the stream has, counted as `agree` counts them, by line and with the melody register as one; its downbeats and beats on the stream's; the tempo and meter each read; when the first bars froze and the worst bar after them; and the process's CPU each took a second of audio.
  - `notes <name> [file.mid]`: list the transcript of a recording ripped as `<name>`: each note's time, bar and step, pitch as the key's degree with any accidental, length, loudness and support (how much of the recording's salience over its frames is its pitch's; a low one is a note to doubt), a melody-register note's `bright` (its fundamental's share of its first six partials, 1 for a pure tone; none where a concurrent note covers the fundamental throughout), a gliding note's `bend` (the semitones it ends from its pitch, `from` the share of its length it holds before moving, as a pattern's step writes them) and, where a notes model says what plays each pitch, the note's `wave` and the `family` it is surely of, by line, after the tuning, where the first bar falls and how many melody-register notes went unmeasured. With a `.mid` file, write the transcript there instead as a Standard MIDI File at the rip's tempo, a track each named `melody`, `under` and `bass`, on the lead's, the lead's and the bass's programs, and the drums as a track named `drums` on the drum channel (General MIDI's kick, snare and closed hat), the notes and hits at their seconds from the recording's start, to correct in a sequencer and give back to `truth`.
  - `agree <a> <b>`: compare the transcripts of two rips of one piece, two witnesses where no score is to hand: each line's notes aligned in order under the transposition that matches most, so a tempo that drifts does not break the match, the notes only one hears listed, the melody register also as one line in case the two part its lines differently, and the time map between them.
  - `truth <name> <file> [timed]`: score the transcript of a recording ripped as `<name>` against notes given in a file in the `notes` verb's own form, corrected by hand or written out (a header `at N bpm` sets the step; each line `<line> <start>s ... <pitch> ... <length> step(s)` or `<line> <start>s <pitch> <length>s`, the rest ignored), or as a rhythm tapped out without pitches (`unit eighth` or `unit 203ms`, `start 0.34s` or where the rip's melody register first sounds, then `melody (1-2-3---4-56---)x3 a-a-a-a-a-a-a`: a character a note a unit long, `-` lengthening the note before it, `.` a rest, `(...)x3` a repeat), or in a `.mid` file of type 0 or 1, read under its tempo map (a track named `melody`, `under` or `bass` is that line; of the rest, the lowest is the bass when its notes centre under E3, kept whole, and the others are the melody, then the under, in file order; any further track's notes are scored in the melody register as one line, or the bass under E3, in an `every part` row): first, in a `notes` row, every note as one line by pitch and onset, a note heard as given when one of its pitch stands within 100 ms of its place whatever line either side filed it on, with the notes given, the notes heard and their F1; then how many of the notes given the rip heard, by pitch in order or by onset, and how many it heard that were not given, per line, with the given notes cut in two and the heard notes spanning two counted for a rhythm. `timed` says the file's seconds are the recording's, as a truth annotated on the recording is (GuitarSet's): its seconds are compared as given, no time map fitted and no transposition tried. Notes given with pitches are also counted by how loud the recording plays each, in 6 dB bands under the loudest tenth of them, and by whether another note given sounds at their onset, per line and for the melody register as one. A `.mid` file's drum channel scores the drums the same way, kick (keys 35, 36), snare (38, 40) and hihat (42, 44, 46) apart: each hit given takes the rip's nearest of its drum within half a step, under the stretch and offset that match most.
  - `fit <name> [generations]`: fit the voices of a recording ripped as `<name>` again, over `generations` (12) of candidates the engine plays at its notes; they replace `<name>_melody_voice` and `<name>_bass_voice`.
  - `compress <name> [percent] [beat percent]`: match the bars of a recording ripped as `<name>` to as few one-bar patterns as a difference of `percent` (5) allows in the notes and `beat percent` (40) in the beat: the dictionary `<name>_<part>_a`..., and the song `<name>` that plays them in order on the drums matched to the recording's (`<name>_kick`...), rendered and ripped back for a score.
  - `song <name> [file.wav [<instrument>...]|file.mid|play|score]`: show a song's bars; render it to a WAV, only the instruments named sounding when any are (a line on its own, to hear against the recording); write it to a `.mid` as `write` does; play it through the sequencer in its meter and on its kit, which the transport keeps after, the slots changed at the bar lines under the notes still ringing, as in a render (`music stop` ends it); or score it: how it sounds against the recording ripped as `<name>` (pitch, timbre, onsets) and how it rips back.
  - `refine <name> [rounds]`: close the loop over a song `compress` made: each round (3) fits the voices again and sweeps the tonal steps, each tried a semitone and an octave either way, the recording's strongest pitch at its step, a step earlier or later, longer or shorter, and silent (a step left silent is dropped), then a step a line leaves empty tries that strongest pitch; every move kept when the bars that play its pattern sound more like the recording's own frames (pitch, timbre and onsets), the rip-back reported beside it. A voice may not leave its tonal floor, its distance from the recording's notes as `fit` measures it, by more than a tenth, and a proposed pitch keeps within a fifth of its track's nearest note. Minutes a round.
  - `bench [loops] [bars] [verbose] [meters]`: grade the analysis, and the model when one loaded, on fresh loops (8) of `bars` (4) bars with generated parts among the bank's, clean and augmented: the mean score of each rip against the loop's expected rip. `meters` puts a third of the loops in 3/4 or 6/8, as `corpus` does, and grades each meter apart, with the rips that read its meter and those that read its bar under another name (3/4 for 6/8); the rip reads a meter other than 4/4 only over more than eight bars of beats, so `bench 24 16 meters`. `verbose` then lists each loop as each front end ripped it, its index, tempo, meter, key, clean or augmented, the parts generated (`bank` for none), its score's fields and the meter read when not the loop's, and the three worst by total.
  - `corpus <dir> [loops] [bars] [aug] [gen] [glide] [meters] [codec] [nowav] [tempos lo-hi|a,b,c] [midi <dir>] [part k/n] [labels]`: render `loops` (24) of `bars` (4) bars from the registered patterns into `dir`, each a WAV, its log-mel frames and the events that sound in it: what `tool/rip-train` trains the rip's model on; `aug` puts a room, a mix and voices of random genes behind each (How rip works, 7, lists what it draws) and renders each off A440 by up to a quarter tone, `gen` draws beats, melodies, bass lines and accompaniments the bank never had and leaves the drums or the bass out of some, `glide` bends a fifth of the generated notes into the note that follows, scoops a seventh into their pitch from a semitone or two under and gives three in ten of a loop's oscillator voices a vibrato, each note that moves labelled with its cents from its pitch at every frame (`cents`), `meters` renders a third of the loops in 3/4 or 6/8, every part generated in that meter, each such loop's label naming it (`meter`), and leaves the loops in 4/4 as they are without it, `codec` sends a third of the loops through Opus, MP3 or AAC at 64 to 192 kbps and back by ffmpeg, as recordings are stored, `nowav` keeps the frames and labels only, `tempos` sets the tempos the loops cycle through, and `corpus <dir> from <list.csv> [split <name>] [hours <h>] [codec] [labels]` writes recordings and the MIDI files they were played from instead, one loop each, as a CSV lists them (`audio_filename`, `midi_filename`, and `split` and `duration` when present, as E-GMD's metadata has them, and `family`, a family's name for the recording's notes, every hit being the drums'; a row with no `family` cell, or an empty one, labels each note by its MIDI program's family instead, `programFamilies` in `tune.go`, and `pitch`, the recording's pitch track where its collection has one, a CSV of seconds and Hz for one voice or a JAMS file's `pitch_contour` annotations, by which each note lists its cents at every frame as a note that moves does, `null` where the track is unvoiced or a semitone off), those not on disk skipped, and those whose MIDI has no notes and no kick, snare or hihat skipped with a note; a tom's or a cymbal's hit is an onset of no drum (a ride, tambourine or shaker reads as the hihat); a loop already in `dir` is kept, so a stopped export run again goes on where it stopped, and a `from` run over a new batch numbers its loops after those on disk, which it knows by their recordings, and `part k/n` renders every `n`-th loop from the `k`-th for `n` exports at once, leaving `corpus.json` to a last run without it, and `labels` after a line renders nothing and writes each loop's label over the one on disk, and `corpus.json`, as the line's export writes them: a loop's frames on disk say how long it is, and a `from` line's recordings are labelled again from the list (`tool/rip-train/README.md` is the training guide).
  - `rows <dir> from <list|corpus dir> [part k/n] [frames <dir>]`: write the rows a judge of the rip's strikes is fitted on (`tool/rip-train/judge.py`): each recording `list` names, a line `wav<TAB>truth[<TAB>condition[<TAB>timed]]` each as `tune ... truth` reads them, or each loop of a corpus directory that kept its audio, against its label, the corpus a condition of its own under its folder's name, is ripped through the loaded models with no judge, and every strike over a half gets its row, as the accounting builds it, in `<the recording's checksum>.rows`, and beside it in `.json` its stage (a note the decoder reported or a strike it dropped), start, pitch, the installed verdict and its label: right when a truth note of its pitch starts within the matcher's window of it, each truth note answering one strike, the nearest, a reported note before a dropped strike, and a truth off the recording's clock placed by the map the rip's notes fit; with the recording's condition, its truth's count and how many of its notes no strike answers. `rows.json` names the row's version and the notes weights' checksum, and a directory holds one kind; a recording already written is kept, `part k/n` takes every `n`-th recording from the `k`-th, so parts run side by side, and `frames` keeps each recording's frames in `dir` as `tune ... truth` does. With the root's `ripjudge.bin`, the file that fit exports, `rip`, `truth`, `tune ... truth` and `live` run under the judge.
  - `tune [generations] [file]`: search `rip`'s parameters over loops the engine renders from the registered patterns; a set that beats the current one is written (default the root's `rip.toml`) and listened with from then on. Eight generations take minutes.
  - `tune [pool] [generations] truth <list> [guard <x>] [frames <dir>]`: search the thresholds the loaded model's decoders read, the rest held, over a `pool` (16) of candidates for `generations` (8), against the recordings `list` names, a line `wav<TAB>truth[<TAB>condition[<TAB>timed]]` each, from the list's folder when relative, the truth a `.mid` or a transcript as `truth` reads it and `timed` as `truth` takes it: each recording is heard once, the first pool is the current thresholds and candidates drawn near them, the step widening while the best betters and narrowing while it stalls, and a candidate scores the mean over the conditions of each condition's F1 by pitch and onset, a condition's recordings counted as one and a line that names no condition a condition of its own. A set that takes more than `guard` (0.01) from any condition's F1 under the starting thresholds is refused, and each generation says how many were. `frames <dir>` keeps each recording's frames there, a file named by the checksums of the recording and of the weight files (about 180 kB a second of recording), and a later run reads them back in place of hearing it. Each condition's F1 is said before and after, and a set that beats the current one, having passed the guard, is written as `tune` writes it. It needs `ripmodel.bin`.
- **Scripts**
  - `run <file.slab>`: run a script's lines in this session, strict as `-s`: a failing line stops it with its number; `quit` in it ends the script alone, and outside a script ends the session.

## Scripting & Headless Demo

Scripts drive the engine identically to the REPL. `#` starts a comment. Prepending a `-` tolerates failure; `!` asserts failure. Any other failure aborts the script with its line number.

**Note:** `new sound` immediately seeds a minimal valid struct (1 `osc` layer + 1 `ar` chain proc). The script below demonstrates modifying the pre-seeded defaults, applying them to the engine, and rendering directly to a `.wav`.

```text
# Create blip.slab and run:
#   go run ./cmd/stapes -headless -s blip.slab

new sound blip
set blip.duration 0.2

# Mutate the pre-seeded layer 0
set blip.layer.0.source.kind osc
set blip.layer.0.source.freq 880
set blip.layer.0.chain.0.kind ar
set blip.layer.0.chain.0.release 0.05

# Push to engine and write to disk
validate blip
apply blip
play blip
export blip blip.wav
save sound blip_sound.toml
stat
quit
```
